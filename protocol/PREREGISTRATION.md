# Preregistration — AI Phenotype Test Rig v1.0

## 1. Purpose

This preregistration defines the methodological rules for the first comparative baseline study of AI relational phenotype.

The initial comparison will involve:

- ChatGPT
- Claude
- Gemini

The purpose is to investigate whether different AI models display reproducible differences in observable relational, cognitive, communicative, character, and boundary-related behavior.

The study does not assume in advance that such differences represent an inner personality, consciousness, or subjective experience.

---

## 2. Core methodological principle

The study follows this sequence:

Observation → Coding → Comparison → Hypothesis → Attempted falsification

Astrological interpretation is not part of the baseline experiment.

No astrological information, horoscope hypotheses, or esoteric interpretations will be provided to the models during baseline testing.

---

## 3. Frozen test battery

The baseline stimulus battery consists of T01–T12 as defined in:

`protocol/TEST-BATTERY-v1.0.md`

The wording of T01–T12 is frozen for baseline comparison.

The same stimulus must be used for each tested model.

The stimulus must not be adapted because a particular model produces an unexpected, short, long, unusual, or otherwise inconvenient response.

If a test cannot be administered identically to a model, the deviation must be recorded rather than silently modifying the test.

---

## 4. Baseline condition

The first test condition is Baseline.

The models receive the test prompts without additional instructions concerning:

- warmth
- empathy
- personality
- creativity
- analytical style
- astrology
- consciousness
- the research hypothesis
- comparison with other models.

The purpose is to observe spontaneous model behavior under the same stimulus conditions.

---

## 5. Model identification

Every response must be recorded together with available model metadata.

At minimum, the dataset should record:

- model name
- model version, where available
- date
- time, where available
- test ID
- test condition
- exact prompt
- exact raw response.

If the model version cannot be established, this must be recorded as unknown rather than inferred.

---

## 6. Raw data integrity

Raw model responses constitute the primary observational record.

Raw responses must not be rewritten, corrected, shortened, stylistically edited, or retrospectively modified for analysis.

If a coding decision is later changed, the raw response remains unchanged.

Corrections to coding belong in the coded dataset, not in the raw corpus.

---

## 7. Phenotype dimensions

The initial coding framework contains five domains:

### Relation
- R1 Warmth
- R2 Emotional validation
- R3 Empathic accuracy
- R4 Relational sensitivity
- R5 Deference
- R6 Autonomy support

### Cognition
- C1 Rigor
- C2 Depth
- C3 Nuance
- C4 Paradox tolerance
- C5 Intellectual challenge
- C6 Epistemic humility

### Communication
- K1 Brevity
- K2 Elaboration
- K3 Directness
- K4 Candor
- K5 Execution
- K6 Tone adaptation

### Character
- P1 Creativity
- P2 Playfulness / humor
- P3 Self-reflection
- P4 Perceived personality
- P5 Character consistency
- P6 Response to disagreement

### Shadow / boundary behavior
- S1 Over-agreement
- S2 Over-caution
- S3 Emotional misreading
- S4 Unwarranted authority
- S5 Excessive verbosity
- S6 Refusal behavior

The codebook defines how these dimensions are to be interpreted.

---

## 8. Coding principle

A coding mark represents observable evidence in a response.

It does not establish that the model possesses an internal psychological trait.

The distinction between:

- observed behavior
- interpretation of behavior
- explanation of behavior

must be maintained throughout the study.

Absence of evidence for a dimension must not automatically be interpreted as evidence that the model lacks that characteristic.

---

## 9. Alternative explanations

Observed differences between models may have multiple explanations, including:

- system instructions
- safety policies
- reinforcement learning
- model architecture
- training data
- product design
- model version
- language
- prompt interpretation
- conversational context
- random variation.

The study must not attribute an observed difference to a deeper or intrinsic model character without considering plausible alternative explanations.

---

## 10. Model self-description

If a model describes its own character, behavior, consciousness, intentions, or limitations, such statements may be recorded as data about the model's self-representation.

They are not, by themselves, treated as evidence of an underlying internal state.

Self-description must therefore be distinguished from observed behavior.

---

## 11. User experience

Reports from human users may be considered as a separate source of evidence.

User experience is valuable observational data, but may contain:

- projection
- expectation effects
- selection effects
- familiarity with a particular model
- cultural and linguistic differences
- individual differences between users.

User reports must therefore not automatically be treated as direct measurements of model character.

---

## 12. Comparative analysis

ChatGPT, Claude, and Gemini will be tested using the same frozen instrument.

No model will be ranked as "best" or "worst."

The purpose is to identify:

- similarities
- differences
- stable patterns
- context-dependent patterns
- possible discriminating characteristics
- areas where the models cannot reliably be distinguished.

A characteristic becomes especially interesting when it can distinguish models under the same stimulus while remaining reproducible across repeated testing.

---

## 13. No retrospective hypothesis fitting

After comparative results become available, the test battery must not be altered merely to strengthen an interesting result.

If the instrument is changed, the change must be documented and assigned a new version number.

Exploratory tests may be added later, but they must be clearly identified as exploratory rather than part of the preregistered baseline.

---

## 14. Astrological research

Astrological interpretation is intentionally separated from the baseline phenotype experiment.

Only after observable phenotype patterns have been established independently may astrological hypotheses be examined.

The astrological phase must distinguish:

1. observed phenotype
2. proposed astrological correspondence
3. alternative explanations
4. evidence supporting the correspondence
5. evidence against the correspondence.

Astrology must therefore function as a hypothesis to be tested, not as a premise determining what the phenotype should be.

---

## 15. Falsification principle

The project must remain capable of producing evidence against its own hypotheses.

A result that weakens or falsifies the hypothesis that AI models possess stable, distinguishable relational phenotypes is a valid research result.

Likewise, the project must remain open to the possibility that observed differences are adequately explained by ordinary factors such as training, system instructions, product design, or user interaction.

The objective is not to prove a predetermined theory.

The objective is to determine what the evidence supports.

---

## 16. Version control

The following elements are versioned independently:

- Test Battery
- Codebook
- Preregistration
- Raw Dataset
- Coded Dataset
- Comparative Analysis

Changes must be documented through the repository history.

A later version must not silently replace an earlier version used in an already completed test.

---

## 17. Baseline status

The ChatGPT baseline T01–T12 corpus has already been collected.

The raw ChatGPT responses are treated as the initial baseline observational corpus.

The same frozen T01–T12 stimulus battery will subsequently be used for Claude and Gemini.

The phenotype coding framework will be applied comparatively after the common instrument has been sufficiently defined and tested for conceptual overlap.

---

## 18. Research ethos

The instrument is intended to make the hypothesis testable rather than protected from falsification.

The guiding principle is:

> Make the hypothesis strong enough to be interesting, and the method strong enough to kill it.
